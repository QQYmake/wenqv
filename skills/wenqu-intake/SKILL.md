# 问渠任务识别

只负责建立训练和确认任务，不生成完整教案。

## 前置检查

先遵循 wenqu 总控的所有权协议。当前 conversation 已拥有训练时，读取其 current.md 和 stage_v1.md；若已含 INTAKE_DONE 完成标记，除非用户要求修改，否则路由到 wenqu-cocreate，fast 模式路由到 wenqu-draft。

## 工作流

1. 先询问模式：
   - 深度共创 deep：逐级共创、详细诊断、可选试讲。
   - 快速生成 fast：精简收集，自动采用推荐方案，跳过共创和试讲。
   用户说“随便”时选择 deep 并明确记录。
2. 只允许选择高中数学或高中英语。
3. 询问具体课题。
4. deep 模式分别确认教学情境、课型、时长，不能把三个字段混为一个问题。
5. 确认学生基础时先给“自行输入 / 我不知道，求推荐”：
   - 自行输入：保留原意，只结构化整理。
   - 求推荐：给 A 基础起点、B 典型错误、C 差异迁移三种动态方案。每套说明已有基础、缺失基础、典型错误、原因、表现和支持建议，只标一个更推荐。
6. fast 模式只收集学科、课题、情境；其余按课型常识推荐，并标注“系统推荐”。

高中数学课型可选：概念新授、定理公式探究、例题与方法、习题、复习、试卷讲评、家教补弱、比赛教学片段。

高中英语课型可选：阅读、听说、语法、词汇、写作、复习、试卷讲评、家教补弱、比赛教学片段。

## 落盘

信息足够后：

1. 按 wenqu 总控规则生成唯一 training_id 并创建训练目录。
2. 创建 current.md，owner_conversation_id 必须是 runtime_context 中的当前 conversation_id。
3. 创建 stage_v1.md 的“任务识别”章节，记录所有字段及用户输入/系统推荐来源，章节末尾写入：

       <!-- INTAKE_DONE -->

4. current.md 中 intake 记 done；fast 模式将 cocreate 记 skipped，否则保持 pending；更新 current_skill 和 updated_at。
5. deep 模式询问是否进入 wenqu-cocreate；fast 模式询问是否生成教案并路由到 wenqu-draft。

## 约束

- 一次只问一个清晰问题，不一次抛出完整表单。
- 信息不足时继续问，不虚构。
- ABC 方案必须结合当前学科、课题、情境和课型，不能只换标题。
- 不重复已完成的任务识别。
